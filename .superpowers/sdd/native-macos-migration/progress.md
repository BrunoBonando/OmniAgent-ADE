New Important findings (whole-branch/cross-task seams invisible to any single task's own reviewer):
1. **Cross-process brain.db rebuild orphans the other process's Store.** `roots.rs`'s `rebuild_store` unlinks+reopens `brain.db`; the daemon and the Tauri app each hold a long-lived `Store` handle now (previously only one process did). "Rebuild brain" from either app during the Task-7-mandated co-existence period silently orphans the other's handle — its subsequent settings/brain writes (layout, notifications, usage) go to a now-nameless inode and are lost on next daemon restart. Fix: daemon should stat the `brain.db` inode before each operation and reopen on change, or a shared generation-counter/lock file.
2. **3 of 4 Task 1 compat fixtures have no Swift consumer** — including `persisted-layout.json`, the most consequential shared contract (the `layout` row every saved tab lives in, read/written by both apps against one `brain.db`). Only `pane-grid.json` is asserted from both languages. Fix: add the 3 missing Swift-side fixture tests mirroring `PaneGridTests.swift`'s pattern.
3. **The release pipeline's final gate can never pass, and its precondition check is warn-only.** `dist.sh verify`'s smoke check still speaks Task 1's obsolete JSON-over-newline protocol (confirmed pre-existing by Tasks 6d/7, but never fixed) — permanently red. `dist.sh sign()` only warns (doesn't hard-fail) when the daemon binary is missing, relying on `verify`'s bundle check as backstop — a backstop inside a subcommand nobody can trust the exit code of. Fix: split the broken smoke check behind an explicit `--with-smoke` flag so `verify`'s exit code means something again, and make `sign()` hard-fail on a missing daemon binary.
4. **The native app has no version wiring** — ships `CFBundleShortVersionString = 1.0` on every build forever (no `MARKETING_VERSION` in any Xcode configuration), breaking the exact mechanism Task 7's cutover gate depends on (`cutover.sh record --version V` needs a real, distinguishing native-app version). Fix: set `MARKETING_VERSION` in Release/Preview configs, extend `bump-build-version.sh`'s existing anchored-regex approach to the Xcode project.
